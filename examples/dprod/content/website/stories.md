# A shared description across teams

Imagine a team offering a dataset to several other teams. A file location alone
does not explain the product's purpose, who owns it, or which access service to
use. Those details often end up in separate conversations.

A DPROD description gives those conversations a shared structure. The team can
identify a data product, describe its purpose, name its owner, and connect it to
its datasets and access mechanisms.

This is an illustrative story, not a report of a deployed customer system.
Stories explain motivation; guides explain a path through the concepts; the
specification defines the vocabulary and constraints.
